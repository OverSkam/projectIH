# App Stein — Architecture (v2.1 rules)

> Where older sections below mention feeding the Goblin, sack slots, `HallScale`, `FilmGrain`, the HUD countdown or tribute rings, the sections **v2.1** and **v2.2** at the end override them.

Godot 4.7.2 .NET, C# only. Everything (scenes, meshes, UI) is built in code; `scenes/Main.tscn` is a single node with `src/Core/Main.cs`.
Game data lives in static C# registries (`src/Items/Defs.cs`), not `.tres`.

## Build / run / test
- Editor: open the folder in Godot 4.7.2 .NET, press Play (the editor builds the C# project itself). Main menu: Host / Join.
- CLI build: `dotnet build AppStein.csproj` (must end with 0 errors). First-time/CI import: `godot --headless --path . --import`.
- Command-line args (after `--`): `--host`, `--join=<room code | ip | ip:port>`, `--name=X`, `--port=N`, `--autostart=N` (host starts when N players are present),
  `--preset=debug` (60 s rounds, quick weighing ceremony, 10 s downed time), `--preset=soak`, `--roundsecs=N` (round length override), `--tribute=Name=N,...`
  (server: sets that tribute weight at every round start; test/screenshot staging), `--give=[Name=]stein:id|util:id|ore:id`,
  `--bot=<routine>` (`idle`, `miner`, `killer`, `pit`, `explorer`, `t_*` item-test bots), `--timeout=<sec>`, `--password=<pw>` (host and join), `--noupnp`, `--nosteam` (never start Steam), `--fakesteam` (screenshots only: the UI behaves as if Steam were there), `--botdebug`, `-- --steamcheck` (headless self-check of the Steam transport, Steam room codes and the Steam-missing path, see "Steam"), `-- --netcheck` (headless self-check of room codes / password hash), `-- --voicecheck` (voice rules, jitter buffer, codec; see "Voice chat"), `--fakevoice` (+ `--voicetalk=lobby+round+weigh|always`, `--voicelevel=0.25`, `--voicepin=Name:x:y:z,...`, `--voicemute=Name`, `--voiceabuse`: fake microphone and test hooks for `tools/voice_test.sh`), `-- --printcode=IP[:port]`, `-- --weighcheck` (headless self-check of the elimination rules).
  Any of host/join/bot = "automated": the process quits itself after the match ends or the host disappears.
- Network test: `tools/net_test.sh` (env `PORT`, uses `PORT+1` too, `LOGDIR`, `TIMEOUT`): room code, password handshake, refusals, brute-force brake, join by code.
- Voice test: `tools/voice_test.sh` (env `PORT`, `LOGDIR`): the whole voice pipeline headless over ENet with a fake microphone, see "Voice chat".
- Interaction test (shove, spill, pickpocket, sack step, downed options): `tools/interact_test.sh` (env `PORT`, `LOGDIR`); see "v2.3" at the end.
- Loot test (geodes, chests, mimics): `tools/loot_test.sh` (env `PORT`, `LOGDIR`, `L2ONLY=chest,mimic`); see the section "Step 2" at the end.
- Smoke test: `tools/smoke_test.sh` (env `PORT`, `LOGDIR`, `TIMEOUT`). Builds, imports, runs the weighing-rules self-check, then host (idle bot) + `Alice` (miner bot)
  + `Bob` (killer bot) as separate headless processes, debug preset, ~3 min: Alice feeds (tribute credited to her client only), Bob hides outside the Hall and
  weighs zero, the reveal sequence is identical on every peer, Bob is thrown and stays a ghost, round 2 is the final two, Alice wins. Processes print
  `PASS: <name>` / `FAIL: <name>`; the script requires every expected PASS, no FAIL, no `ERROR`/exception text. Exit code non-zero on any problem.
  **Run it before every commit that touches gameplay or networking.** When adding a feature, add a PASS line in the code and the name to the script's list.

## Autoloads and nodes
- `Net` (`src/Net/Net.cs`): ENet listen-server (port 7777, 8 peers), lobby roster `Net.Names` (peer id -> name), events `LobbyChanged/Connected/ServerLost/PeerLeft`.
- `Game` (`src/Core/Game.cs` + partials `Game.Weighing.cs`, `Game.Downed.cs`, `Items/Game.Items.cs`): match/round state machine (server) + **all in-round RPCs**.
  Phases: Lobby -> Round -> Weighing -> (next Round | MatchEnd) -> Lobby. Public per-miner state: `Game.Status` (Alive / Downed / Dead / Eliminated).
- `World` (`src/World/World.cs`, child of `/root/Game/World`, re-created every round on every peer): `Geometry` (cave), `Miners` (children named by peer id),
  `Objects` (networked objects), registry `World.Objects[id]`.
- `Main` (scene root) owns UI layers: `MenuUI` (menu+lobby), `Hud`, `Screens` (round summary / match end). UI only reads `Game`/`Net` state and events.
- Server-only per-player record: `ServerPlayer` (`src/Player/ServerPlayer.cs`). Clients never have one.

## RPC and authority conventions (follow strictly)
- No MultiplayerSpawner/Synchronizer. Everything is an explicit RPC declared **on `Game`** (an always-existing node, so no "node not found" races).
- `Request*` / `Report*`: client -> server. `[Rpc(AnyPeer, CallLocal = true, Reliable)]`, called as `RpcId(1, ...)`. The handler starts with
  `if (!Net.I.IsServer) return; var p = Sender();` (`Sender()` maps remote id 0 to the local host) and then **validates** (alive, phase, cooldown, distance, slot space).
- `Client*`: server -> clients. `[Rpc(Authority, CallLocal = true, Reliable)]`; the server's own process runs the same handler, so the host is just another client.
- Movement: the owner simulates its miner and sends `ReportState` (unreliable, ~20 Hz); the server stores it in `ServerPlayer.Pos` and forwards `ClientState`
  to the other peers, which interpolate. Fall damage is reported by the owner (`ReportFall`) and clamped/validated by the server.
- Server-authoritative: health, damage, downed/death, inventory, tribute weight, lantern oil, round state, the weighing, world objects, loot bags.
- **Hidden information:** tribute weight, inventory and oil go only to their owner via `RpcId(peer, nameof(ClientOwnState), ...)` (`SendOwnState`) and
  `ClientFeedAck`. The handlers assert `owner == MyId` and log `FAIL: foreign_state_received` / `foreign_feed_ack` otherwise (the smoke test would catch a leak).
  Public: position, status, downed, held utility, whether a lantern is lit / flickering / out, announcements, Goblin cues (`ClientGoblinCue`: category + seed, every peer picks the same line),
  and everything the weighing reveals (a pile's weight is sent only when it is revealed). Loot-bag contents stay on the server (`BagObj.Items`) until looted.
- Late joiners: `OnPeerRegistered` -> they never were miners: marked `Eliminated` (ghost for the rest of the match), `ServerSendSnapshot` if a round is running.
  A miner who disconnects is eliminated at once (`OnPeerLeft`); if at most one miner remains at any moment the match ends with them as winner (`CheckMatchOver`).
- Physics layers: 1 world, 2 miners, 4 solid objects (veins, goblin), 8 pickups/bags (interaction rays only).

## Adding content
**Ore**: add an `OreDef` in `Ores` (`Defs.cs`): id, `TributeWeight` (weight on the Scale), colour, glow, `MinDepth`, `SpawnWeight` (relative pick chance; 0 = never spawns, e.g. the Midas `statue`).
Veins/loose ore pick via `Ores.Pick(rng, roomDepth, round)`. Power steins weigh `Steins.TributeOf(id)` when fed (Common 6, Rare 12, Legendary 20).
**Stein**: add a `SteinDef` in `Steins`: `Modify(StatBlock)` for passive stats (speed, jump, damage taken, melee, mining speed, sack bonus, regen, no-fall),
`OnTick(ServerPlayer, dt)` for per-tick server logic, `OnEvent(ServerPlayer, SteinEvent)` for `RoundStart/RoundEnd/DamageTaken/DamageDealt/Kill/Death/Fed/Mined`
(`RoundEnd` fires after the lock-out, before the weighing piles are built: the Blood penalty lives there).
Stats are recomputed by `ServerPlayer.RecalcStats()` whenever steins change; the owner receives speed/jump/no-fall in `ClientOwnState`. New stat = add a field to `StatBlock`
and use it where the server (or the owner via OwnState) applies it. `Steins.RandomCommon` picks the starting stein, so a new Common is automatically in the pool.
**Utility**: add a `UtilityDef` in `Utilities` (placeholders for Rope, Gas mask, Map, Dynamite, Bear trap exist with `Stub = true`). Held visuals are in `Miner.SetHeld`.
Behaviour for "use utility" (RMB, action `use_utility`) is not wired yet: add `Request UseUtility` in `Game`, validate on the server, replicate results as `Client*` RPCs.
**Interactable / networked world object**: subclass `NetObject` (`src/World/NetObjects.cs`), implement `Build()` (visuals + collision, layer 4 solid or 8 pickup),
`Prompt(inv)` (text starting with `"E"` makes it interactable), `ServerInteract(p)` and/or `ServerHit(p, mining, pickaxe)`; register in `NetObject.Factories`.
Spawn on the server with `Game.I.ServerSpawnObject(kind, pos, data)` (assigns the id, replicates), change with `ServerSetObjectData`, remove with `ServerDespawnObject`.
`Data` is a string (`Kv()` helper); anything secret must stay in server-only fields. `ApplyData` runs on every peer.
**Server-driven monster / trap**: make it a `NetObject` kind; the server runs its AI in `_PhysicsProcess` only when `Net.I.IsServer`, moves it, and replicates
position/state either through `ServerSetObjectData` at low rate or a new `Client*` RPC (unreliable for position). Damage goes through `ServerPlayer.TakeDamage(amount, source, cause)`
(applies stein modifiers and kills correctly). Spawn from cave markers (`Game.MarkerSpawners`). Monsters are unkillable: derive from `MonsterObj`, use `Stun(seconds)` for anything that should interrupt them.
Use `World.Cave.FindPath` / `NavNodes` for coarse navigation.

## Cave builder
`ICaveBuilder.Build(Node3D parent, int seed, int round)` -> `CaveInfo` (`src/World/CaveInfo.cs`). It runs on **every peer** and must be deterministic for a given seed
(geometry only; networked objects are spawned by the server from the markers). Swap the implementation via `World.Builder`. `CaveInfo` contains:
the **Hall of the Scale seams**: `HallZone` (AABB; the miners inside it when the timer ends are counted; no PvP, monsters/traps/explosions do nothing there; `InHall(p)`; the old name
`CampZone` is kept as an alias property on `CaveInfo`), `GoblinPos`, `PalmPos` (the Goblin's open palm: the feeding point; stones are fed by interacting with the Goblin object, steins by
holding interact, validated within 5.5 m of the palm), `ScalePos` (centre of the weighing platform; `HallScale` builds placeholder visuals there), `WeighSpots` (>= 8 standing places inside the Hall,
one per miner in peer-id order, all facing `ScalePos`; `MakeWeighSpots` lays them on an arc), `ShaftPos` (where the thrown miner falls into the dark),
`MinerSpawns` (>= 8), `Rooms[]` (`Bounds`, `Center`, `Depth` from the Hall, `Markers[]` with `Kind` = `vein | ore | monster | dragon | trap | lever | loot | chest | shrine | oil` and `Pos`),
and a waypoint graph `NavNodes/NavEdges` (`FindPath`) used by the bots. Keep the Hall lit (OmniLights) and everything else dark; the world environment has no ambient light (`World.BuildCave`).
`--cavecheck` verifies the seams (spots inside the Hall, >= 8, distinct). `ModularCave` uses the `camp` module as the Hall (legend char `i` = oil drum marker); `GreyBoxCave` is the old grid cave.

## Round/match rules implemented (`Game`, `MatchConfig`)
- N miners = N-1 rounds (`MatchConfig.RoundsFor`). Round timer: 6 min +1 per round up to 10 (`Config.cs`; presets `debug`, `soak`).
- **Tribute:** `ServerPlayer.TributeWeight` (server-authoritative, owner-only, reset to 0 after every weighing). `Game.ServerFeed` feeds the whole sack (tap interact on the Goblin),
  `Game.ServerFeedStein` one stein (hold interact ~1 s at the Goblin, `RequestFeedStein`, shows a hold bar). Fed items are gone. Goblin cues `feed_small/feed_large/feed_stein` are public.
- **Timer end -> `ServerBeginWeighing`** (phase `Weighing`): a living miner outside `HallZone` weighs zero and loses everything carried (`NeedsKit`: back next round with pickaxe + lantern, no stein);
  `RoundEnd` stein events run (Blood, Infinity; an Infinity win ends the match before any weighing); piles are built; everyone left in the match (also ghosts) is revived and placed on `WeighSpots`.
  Early end when every miner in the cave is dead.
- **Weighing ceremony** (`Game.Weighing.cs`, server timeline in `AdvanceWeighing`, client state `Game.Weigh` + `WeighChanged`): Intro -> Reveal x N (heaviest first, lightest last; `ClientWeighReveal`
  carries the weight) -> Verdict (`Weighing.Resolve`) -> Throw (`ClientWeighThrow`: `Miner.StartThrow` lifts the miner to the palm, over `ShaftPos` and drops them; the victim's camera is on the miner) -> "N miners remain" card
  -> next round, or match end after a final weighing. Presentation: `WeighingUi` (overlay), `HallScale` (placeholder platform + number in the world), Goblin lines via `GoblinCue`. Timings are in `MatchConfig`.
  Rules (`Weighing.Resolve`, unit-checked by `--weighcheck`): lightest thrown; ties: all tied thrown unless that leaves nobody (then one at random); final two: heavier wins (tie: random).
- **Hooks for later steps** (server): `Weighing.Prepare(WeighingContext)` once before the first reveal (Liar swap, gifting, Pact stone: change piles only through `WeighingContext.Add/Set/Swap`),
  `Weighing.BeforeReveal(WeighingContext, WeighPile)` right before each miner's pile is revealed (per-miner step).
- **Eliminated players** stay as ghosts: everything the role does is behind `EliminatedRole` (`OnEliminated`, `OnRoundStart` on the server, `ClientEnter` on the client). The Turned replace its bodies.
- **Downed** (`Game.Downed.cs`): at 0 health `DownMiner` -> `ServerPlayer.Downed` for `Config.DownedSeconds` (30): crawls at 12% speed, cannot act (`Game.CanAct`), visible lying pose (`Miner.IsDowned`),
  HUD countdown; `RequestLoot` takes one item per press (sack, steins, utilities); further damage or the timer kills (`KillMiner`: bag, ghost, back next round). Seam for dragging / reviving: `ServerRevive`,
  `ServerPlayer.DownedBy`, `Miner.LootTarget`.
- **Lantern oil** (`ItemsServer.TickLantern`): `ServerPlayer.Oil` (seconds, `Config.LanternOilSeconds` = 240, full at every round start, owner-only), `LanternOn` (toggle key L, `RequestToggleLantern`).
  Oil burns only while the lantern is lit and held. The public light state (0 lit, 1 out, 2 flickering at <= 25%) goes through `ClientLantern`. `OilDrumObj` (marker `oil`, `Config.OilDrumRefills` each) refills.
- **Monsters are unkillable:** `MonsterObj.Stun(seconds)` (state `Stunned`); Golem back-crystal hit 6 s, dynamite 2.5 s, bear trap 3 s. Ember Elemental and Gas Wisp classes stay but are no longer spawned. Dragon unchanged.
- Death in the cave is not elimination. Midas: a miner killed by the holder leaves a `statue` stone (weight 15) instead of a bag. Blood: no kill by the weighing -> stein lost and half of this round's tribute.

## Known limitations / stubs
- Ghost meddling is small: right mouse snuffs the nearest lantern for 6 s, E knocks a pebble (cooldown 6 s). Eliminated players are ghosts until the Turned exist.
- Hit detection is a single server ray from the reported eye position; remote miners on the server are interpolated, so very fast movers can be slightly off. No lag compensation.
- Movement is client-authoritative (speed/teleport are not validated). Fall damage is trusted within clamps.
- Peer ids are Godot's random ints (not 1..8). Timings and tribute numbers are first guesses (`Config.cs`, `Defs.cs`).
- Only one thrown miner gets the Goblin's reaching arm at a time (a tie throws the others without a hand). `--cave=greybox` is a legacy test cave: the giant does not fit its small hall (visuals poke through the walls; positions and rules still work).
- Not verifiable headless: visuals, lighting, input feel, mouse capture/pause menu behaviour, HUD layout. Bots navigate only via the nav graph.
- A hard-killed host is noticed by clients only after the ENet timeout (~30 s); a normal quit disconnects immediately.

## Extension points for parallel content work (`src/Core/Seams.cs`) — use these instead of editing shared files
- **Content modules:** a static class marked `[ContentModule]` with `public static void Register()` runs once on every peer at startup. Do all your
  registration there (`NetObject.Factories["kind"] = ...`, `Game.MarkerSpawners["kind"] = ...`, event subscriptions). One module class per workstream, in its own folder.
  Do NOT edit the `Factories` initializer or `Game.PopulateWorld`.
- **Marker spawners:** `Game.MarkerSpawners[kind] = (game, room, marker, rng) => ...` is called on the server for every cave marker of that kind each round.
  Kinds: `monster`, `dragon` (Monsters); `trap`, `lever` (Traps); `loot`, `chest`, `shrine` (Items). `Game.RoundPopulated` fires afterwards.
- **Noise:** call `Game.ServerNoise(pos, loudnessMetres, byPlayer)` on the server when something is loud; subscribe to `Game.NoiseMade` to react (monsters, rockfalls).
- **Damage causes:** pass a cause string to `ServerPlayer.TakeDamage`: `melee`, `fall`, `gas`, `fire`, `crush`, `spikes`, `monster`, `explosion`, `collapse` (the rockfall lever). Damage that takes health to 0 downs the miner.
  `gas` is ignored when `Stats.GasImmune`.
- **StatBlock** already has `GasImmune`, `DarkVision`, `Luck`, `NoiseMul` (owned by the Items workstream; others only read them).
- **Physics layers:** `Layers.World/Miners/Solid/Pickup/ThinWall/Monsters`. Thin (Ethereal) walls are StaticBodies on `Layers.ThinWall` built by the cave.
- **Water:** `CaveInfo.WaterZones` / `InWater(pos)`.
- **New RPCs:** in your own `partial class Game` file inside your folder.

## Seeing the game
`tools/screenshot.sh <outdir> <frames> <game args>` renders off-screen and writes PNG frames (10 frames = 1 s). Open a PNG with your image-reading tool to check
visuals. Software rendering is slow: keep it to a few hundred frames.

## Items workstream (src/Items)
Registered by `ItemsModule` ([ContentModule]). Steins incl. Blood/Infinity (`ItemsServer`, `InfinityTracker`), chests/shrines/loose loot (`Loot`, `WorldObjects.cs`),
utilities via RMB (`Game.RequestUseUtility` -> `ItemsServer.UseHeld`: dynamite, bear trap, rope), active stein key Q (`stein_ability`), L toggles the lantern, F cycles the highlighted stein slot
(swap target), drop ore moved to T. Monsters can implement `IRootable` (bear trap: stun) and `IExplodable` (dynamite: stun). Owner-only item state goes through `ClientItemState`.
Tests: `tools/items_test.sh` (scripted by `--itest=util|infinity|tie|disconnect`, `--give=`, `--debugspawn=`; bots `--bot=t_*`, see `ItemsDebug.cs`; elimination is steered by setting tribute weights).
## Modular cave (src/World/Cave)
Default builder `ModularCave` (`--cave=greybox` selects the old one). 14x14-cell (2 m) hand-built modules in `CaveModules.cs` (ASCII legend in the file), rotated and joined on an 18-cell slot grid.
Debug: `-- --cavecheck` (headless self-check, seeds 1-20 x rounds 1-5), `--caveseed=N --caveround=N`, `--cavelist`, screenshots with `--camroom=N [--camat=<marker kind>] [--camoff=x,y,z --camyaw=deg --campitch=deg]` or `--cam=x,y,z`.
Nav graph = one node per walkable cell (crawl, thin-wall and Hall-furniture cells excluded); `FindPath` is A*. Miners collide with layer 16 (thin walls).


## Step 1B: the look and the space
**Hall of the Scale** (the `camp` module, ceiling 12 m, north door never connected). Local frame (origin = hall centre `h0`, x east, z south): the giant Goblin sits at the north wall
(`CaveInfo.GoblinSeat` = h0 + (0,0,-9.2)); the `GoblinObj` network object (`GoblinPos`) sits on the floor under his feeding palm (seat + (-4.2,0,4.4)); `PalmPos` = GoblinPos + 1.4 m up; bots and the
feed prompt stand 2.3 m in front of `GoblinPos`. `ScalePos` = h0 + (0,0,-1.8) with the gantry posts at x = +-6.2; `ShaftPos` = h0 + (9.4,0,-2); `WeighSpots` = 8 places on a 3.2 m arc around the Scale;
`CagePos` (cage lift on a chain, visual + box collider) = h0 + (-9.5,0,10); `MinerSpawns` rows 9/10. Hall furniture is solid; `ModularCave.HallBlocked` removes nav nodes inside/around it
(`cavecheck` asserts the feeding spot and all weigh spots stay walkable and connected).
**Goblin rig** (`src/Goblin/`): `GMesh` (flat-shaded ellipsoid/tube/box kit with per-triangle colour variation), `GoblinParts` (geometry: the face is a sculpted height field of Gaussian features
- brow, sockets, hooked nose, cheekbones, lips with a smirk, chin, jowls - split into a static upper face and a jaw node; hair, ears, eyes, lids, brows, torso with navy quarter-zip and popped collar, legs, throne),
`GoblinRig` (animation + collision: breathing, blink, ear twitch; eyes follow the nearest miner fast, head slowly; jaw moves while `GoblinVoice.Said` fires; chewing on `feed_*` cues; `React("happy"|"angry")`;
lit from below by sickly green-yellow omni lights). Right hand (world -X) = the open feeding palm (glow disc + "FEED HIM" label, collision slab top at y = 1.45 m); the left arm is a stretchy two-bone IK arm
(bones scale up to 1.5x) that reaches the thrown miner, lifts, swings over the shaft and releases, driven by `Miner.ThrowU` (the same timeline the miner uses: `ThrowReachEnd/LiftEnd/SwingEnd`,
`Miner.ThrowHold/ThrowTop`), with a spotlight on the victim. `HallScale` = the gantry balance (beam tilts with the shown weight, the left pan's pile grows, big number above) + the shaft (wellhead, red glow, solid parapet).
**Tunnels and rooms** (`src/World/Cave/`): connecting tunnels are ONE grid cell wide; a *lattice warp* (`ModularCave.Warp`: cell-corner points pulled inward) turns them into 1.2-1.4 m wide passages, used by both the
mesh (`CaveVisuals.P`) and the collision (`CaveBuilder`: convex prisms fill the gap). Kinds (`TunnelDef.Kind`): 0 ordinary (ceiling 2.1-2.3 m), 1 crawl (middle two cells 1.1 m: crouch only; never the only way
to a room, max 2 per cave), 2 squeeze (0.85 m wide in the middle, `CaveInfo.SqueezeZones`, miners move at 55%). Tunnel mouths (door cells) are 3 m high. Room modules are small chambers with 3.0-5.0 m ceilings (monster rooms
>= 4.4 m; golems have `Headroom` 4 m and cannot enter lower cells, so they stay in their rooms). The miner capsule is 0.32 m radius, 1.0 m high when crouched.
`--cavecheck` additionally asserts tunnel widths/heights from the warp table and the cell grid, crawl count, room ceilings and sizes, that every room is reachable, and the Hall seams.
**Look**: no ambient light, near-black cold rock, exponential fog 0.042, lantern = warm omni (3.0 energy, 13 m range, shadows on). Light sources are only lanterns, glowing ore (emissive + faint light), the Hall's
green-yellow glow, the shaft's red glow and existing effect lights. `FilmGrain` (`src/UI/FilmGrain.cs`, canvas layer 2 under the HUD) draws grain + vignette; toggle in the settings (`UserSettings.FilmGrain`).
The project uses Forward Plus; the screenshot tool and tests run with `opengl3` (Compatibility), so everything above is Compatibility-safe (no Forward-only features).
**Staging views**: `--nohud`, `--camgoblin=entrance|face|q|profile|close|palm|hand|side|throw` (`--camfov=`), `--camtunnel=N [--camback=m --camcrouch]`, `--camdark` (no lantern), `--cavelist` also lists tunnels.
Soak: brave explorer bots deliberately walk over one known damaging trap per match (`_trapRuns`), so `trap_hit_miner` no longer depends on luck.


## v2.1 (bottomless sack, rings, atmosphere, bigger caves)
- **Sack and burden** (`Defs.cs`, `Items/Burden.cs`, `Inventory.Sack`): one unlimited `List<string>` of ore ids per miner; nothing removes stones from it except the weighing, death and robbery. `OreDef.Burden` next to `TributeWeight`
  (Coal 3/1, Iron 3/2, Silver 2/4, Gold 2/7, Ruby 1/10, Diamond 1/14, statue 5/15). Stuffed power steins are ores too (`stein_c/_r/_l`, 6/12/20, burden 1; `Game.ServerStuffStein`, hold G, `RequestStuffStein`). `ServerPlayer.TributeWeight`
  is now computed (sack worth + `TributeAdj` for Blood and `--tribute`); `ServerPlayer.Burden` = sack burden x `Stats.BurdenMul` (Packmule 0.5). The owner gets `burden` in `ClientOwnState`; `Miner` applies `Burden.SpeedMul` (max(0.35, 1/(1+B/36))),
  a sprint stamina bar (drain x(1+B/10)); `ItemsServer.Tick` makes footstep noise via `Game.ServerNoise` (`Burden.WalkNoise/SprintNoise`). The drop-ore action (T) and `RequestDrop` for stones are gone; G taps drop a utility, G held 1 s stuffs a stein.
- **Death and robbery**: `KillMiner` drops the sack as a `bag` (server `BagObj.Items`); `BagObj.ServerInteract` pours all ores into the interacting sack (steins/utilities only into free slots). `ServerLootOne` takes one stone per press, highest tribute first. Midas statue is a `pickup` stone.

## Online play: room codes and passwords (`src/Net`)
- **Room code** (`RoomCode.cs`, pure): public IPv4 + port + CRC-8, scrambled (XOR + odd multiplier mod 2^56, plus a 4-bit fold), Crockford base32, `XXXX-XXXX-XXXX`. Decoding ignores case, spaces, dashes, maps O to 0 and I/L to 1, and rejects a failed checksum ("That code is not valid"). `RoomCode.Resolve` also accepts a raw IPv4, `IP:port` or host name (this is what the Room code field and `--join=` use). It is not a secret, only a convenience.
- **Reachability** (`PortOpener.cs`, child node `Net.Room`): when hosting from the menu, a worker task asks the router for a UDP port mapping with Godot's `Upnp` (discover, `AddPortMapping`, `QueryExternalAddress`), results are marshalled back with `CallDeferred`. If the router gives no usable public address, `HttpRequest` asks `api.ipify.org`, then `ifconfig.me/ip` (bare GET, 5 s timeout). Status `Checking / Ready / Failed` drives the one status line in `RoomInfoPanel` (lobby and pause menu). The mapping is removed on `Net.Disconnect()` and at exit (waits at most 1.5 s). A private/CGNAT external address counts as Failed. Hosting never waits for any of this. All of it is skipped in automated runs (`--host/--join/--bot`), headless runs and with `--noupnp`; `--fakeupnp=ready|checking|failed` fakes the state for screenshots. **Not verified against a real router** (no router in the test container).
- **Password** (`RoomAuth.cs`, handshake in `Net.cs`): uses `SceneMultiplayer` authentication. A connecting peer is *pending*: the engine sends it no broadcasts and drops its RPCs; no `Names` entry, no `ServerPlayer`, nothing is spawned. The server sends a 16-byte nonce and whether a password is required; the client answers `name + SHA-256(nonce + password)`; the server checks with `CryptographicOperations.FixedTimeEquals`. Wrong or missing password, full room (8 players) or a blocked address get a reason packet (`Wrong password.`, `This room needs a password.`, ...), then the server drops the peer 0.5 s later. No answer within 6 s (`AuthTimeout`): dropped. 5 wrong tries from one address within a minute block that address for a minute. `Net.IsVerified(peer)` is the extra guard used by `Game.Sender()`, so every `Request*/Report*` handler ignores peers that did not pass the handshake; `RegisterName` ignores them too. The password is never part of the room code and never sent in clear (the match traffic itself is not encrypted).
- A joining client fails with `Net.FailReason` (invalid code is caught before connecting; 10 s without an answer = "Could not reach the host"). A player who joins after the match started still becomes a ghost spectator (unchanged).

## Steam (`src/Net/Steam`, `third_party/steam`)
The game is released only on Steam. Online play goes through Steam: a Steam lobby carries the invite / room code, `SteamPeer` carries the game traffic over Steam Networking Sockets (Valve's relay network, so no router setup). The ENet / UPnP / IP-room-code path of the previous section stays in the code unchanged (all `tools/*.sh` tests use it on localhost); in the menu it is the fallback when Steam is not running and the "Direct connection (advanced)" button when it is.

**Status: written and tested only without Steam.** The container has no Steam client, so nothing below has ever run against real Steam; see "Never executed against real Steam" at the end of this section.

- **App ID:** `SteamConfig.AppId` in `src/Net/Steam/SteamConfig.cs` and the number in `steam_appid.txt` (project root; `tools/build_windows.sh` copies it next to the exe and refuses to build when the two differ). Now 480 = Valve's public test app "Spacewar" (Steam shows the game under that name; many developers share this App ID, which is harmless: we never list or search lobbies, and our lobbies are only found by ID).
- **Switching to a real App ID** (after the Steam app exists): 1) change `AppId` in `SteamConfig.cs`; 2) put the same number into `steam_appid.txt`; 3) replace `third_party/steam/win64/steam_api64.dll` by the one from the Steamworks SDK 1.60 (`redistributable_bin/win64`); 4) run `tools/build_windows.sh`; 5) for the build you upload to Steam as a depot do NOT ship `steam_appid.txt` (Steam supplies the ID when it launches the game; the file is only for starting the exe by hand); 6) before release also call `SteamAPI.RestartAppIfNecessary(appId)` at the start of `SteamService.InitNative` (not done now, because with 480 it would relaunch the game through Steam on every start). Bump `SteamConfig.GameVersion` whenever the network protocol changes (joiners with another version are refused with a clear message).
- **Native library:** the NuGet package `Steamworks.NET` 2024.8.0 (`AppStein.csproj`) ships only the managed wrapper; the Godot export puts it into `data_AppStein_windows_x86_64/Steamworks.NET.dll` and it imports `steam_api64`. The native `steam_api64.dll` is vendored in `third_party/steam/win64/` (see its README for origin and hash) and copied next to `AppStein.exe` by the build script. On Linux the same wrapper looks for `libsteam_api.so` and does not find it: Steam is simply unavailable there.
- **`SteamService`** (`SteamService.cs`, child node `Net.Steam`): the only place that initialises Steam. `Available` is false when the library is missing, Steam is not running, the struct layout check fails, or the run is automated (`--host/--join/--bot`), headless, or has `--nosteam`; `Status` says which. It never throws outward (all Steam calls are in `NoInlining` methods under `try/catch`, so even a library that fails to load while the method is compiled is caught), calls `SteamAPI.RunCallbacks` every frame and from every `SteamSockets.Poll`, and `SteamAPI.Shutdown` on exit. It also calls `SteamNetworkingUtils.InitRelayNetworkAccess()` right after init, reads the persona name (used as the default miner name when no name was ever typed) and warns in the log when Steam's App ID differs from `SteamConfig.AppId`. `--fakesteam` makes only the UI behave as if Steam were available (screenshots; hosting then fails with a message).
- **Transport** (`ISteamSockets.cs`, `SteamPeerCore.cs`, `SteamPeer.cs`, `SteamSockets.cs`):
  - `SteamPeerCore` (pure logic) holds peer ids, framing, the receive queue and the connect / disconnect logic and talks to Steam only through `ISteamSockets` (`Listen`, `Connect`, `Accept`, `Close`, `Send`, `Poll`). `SteamPeer : MultiplayerPeerExtension` maps the Godot virtuals (`_Poll`, `_PutPacketScript`, `_GetPacketScript`, `_SetTargetPeer`, `_DisconnectPeer`, `_Close`, `_GetConnectionStatus`, ...) onto the core. `SteamSockets` is the real implementation (`CreateListenSocketP2P`, `ConnectP2P`, one poll group, `SteamNetConnectionStatusChangedCallback_t`, `SendMessageToConnection`, `ReceiveMessagesOnPollGroup`). `FakeSteamNetwork.cs` is an in-memory implementation used only by `--steamcheck`.
  - Peer ids: the host is 1. A joiner connects, the host picks a random positive int32 (not in use) and sends a 6-byte hello (`[0x20][protocol 1][id little endian]`); the joiner is "Connecting" until it has the hello, then raises `peer_connected(1)`; the host raises `peer_connected(id)` when it sends the hello. A hello with another protocol version ends the connection with the reason "different version".
  - Framing: 2 header bytes `[kind<<4 | transfer mode][channel]`. Reliable maps to `k_nSteamNetworkingSend_Reliable`, unreliable to `UnreliableNoNagle`. Steam has no ordered-unreliable and no channels, so unreliable-ordered adds a 16-bit sequence number per (connection, channel) and the receiver drops older packets; the channel travels in the header. An "unreliable" packet larger than 1100 bytes is sent reliably (Steam would split it and lose all of it when one piece is lost); the receiver still sees the original mode. Maximum packet size 512 KiB minus header. Targets: 0 = everyone, positive = that peer, negative = everyone except. A client may only target 0 or 1.
  - Closing: `Close` uses linger so that a refusal reason sent just before the drop still arrives; packets already received stay readable after the other side closed. `_SetRefuseNewConnections` and a 16 connection cap close new connections at once.
- **Lobby** (`SteamLobby.cs`, `SteamLobbyCode.cs`): `Net.HostSteam(password, anyoneWithCode)` first opens the listen socket (so the room exists locally at once), then `SteamMatchmaking.CreateLobby` (`FriendsOnly`, or `Public` for "Open to anyone with the code"; Public is the only type a non-friend can join by ID; max 8 members). Lobby data: `host` (SteamID64), `ver`, `game`, `pw` (0/1), `players`, `inmatch` (updated whenever the roster or the game phase changes). Rich presence `connect = "+connect_lobby <id>"` gives "Join Game" on the friends list. Joining (`Net.JoinSteam(lobbyId, password)`, from a typed code, `GameLobbyJoinRequested_t`, `GameRichPresenceJoinRequested_t` or the `+connect_lobby <id>` launch argument, which `Main` handles at start-up) first leaves the current room, calls `JoinLobby`, reads `host` / `ver` / `pw`, refuses a version mismatch or a missing password right there, then connects `SteamPeer` to the host. Every lobby request has a 15 s timeout, a joining client gives up after 25 s; every failure ends as a sentence in the red status line (`Could not create the Steam room`, `Could not join: room not found / full / friends only / ...`) and the menu is usable again. The lobby is left on `Net.Disconnect()` / quit; when the host leaves, clients get `ServerDisconnected` as before.
- **Room code for Steam rooms:** `UXXX-XXXX-XXXX` (`SteamLobbyCode`): `U` + 11 base32 characters = the low 32 bits of the lobby id + a 23-bit check, scrambled like the IP codes (ordinary matchmaking lobby ids have the same high 32 bits, `0x01860000`; any other id gets a 19-character long form with the full 64 bits). The first letter `U` is not in the IP-code alphabet, so the two kinds are never confused (each decoder rejects the other's codes). Forgiving input as for IP codes. `MenuUI` sends a typed `U...` code to Steam and anything else to the direct path.
- **Password and handshake:** unchanged. `RoomAuth` / `SceneMultiplayer` authentication runs over `SteamPeer` exactly as over ENet (`--steamcheck` runs an authentication round trip through the real `SceneMultiplayer`). The brute-force brake keys on `steam:<SteamID64>` instead of the IP address. `Net.IsVerified` is untouched.
- **UI:** Steam running: the menu shows Host game (password, "Open to anyone with the code" tick), Join (room code, password), "or accept a Steam invite from a friend", and a small "Direct connection (advanced)" switch to the old block. Steam not running: one orange line "Steam is not running - start Steam to invite friends" above the old direct block. Lobby and pause menu (`RoomInfoPanel`): Invite friends (opens the in-game friends list, see "Invites without the overlay"), the Steam room code with Copy, one status line (a friends-only room says that friends can also just paste the code). ## Voice chat (`src/Net/Voice`)
Proximity voice for a game about deals and betrayal in the dark. It uses Steam's voice API (no extra libraries), so it exists only with Steam; without Steam (direct connection, tests, headless) voice is unavailable, Settings says "Voice needs Steam" and everything else works unchanged. **Written and tested only with a fake microphone and fake codec over ENet; nothing here has ever run against real Steam voice or a real microphone** (see the end of this section).

- **Seams** (`VoiceSources.cs`): `IVoiceSource` (microphone: `Start/Stop/Poll` returns compressed chunks, `SetSpeaking`) and `IVoiceCodec` (`Decode` to float PCM at `SampleRate`). Real: `SteamVoiceSource` (`SteamUser.StartVoiceRecording`, `GetAvailableVoice` + `GetVoice(compressed)` polled every frame while recording, `SteamFriends.SetInGameVoiceSpeaking` while transmitting) and `SteamVoiceCodec` (`SteamUser.DecompressVoice` at `GetVoiceOptimalSampleRate()`, usually 24 kHz). Fake: `FakeVoiceSource` (a two-tone sine "speech" with a syllable envelope in 20 ms frames, only while a script says so) and `FakeVoiceCodec` (one byte per sample, 12 kHz). `--fakevoice` switches the game to the fake pair on every peer; `--fakesteam` alone only gives a silent stand-in so Settings and the screenshots show the controls (nothing is ever sent).
- **Capture** (`VoiceHub`, child node `Game/Voice`, every peer): modes in Settings (saved in `settings.cfg`): **Open mic** (default; the level of each chunk is measured by decoding it, chunks below the gate `OpenMicGate` are not sent, with a 0.35 s hang), **Push to talk** (hold **V**; the `voice_ptt` input action is registered in code so `project.godot` is untouched; V is ignored while typing in a text field), **Off**. The mic only runs while it is wanted (sending, or the Settings meter is on screen). Chunks go out through a small queue at most every 20 ms (a backlog of more than 12 chunks drops the oldest) as `[seq lo][seq hi][level 0..255][compressed audio]`. A chunk over `MaxFrameBytes` is dropped on the client.
- **Network** (`Game.Voice.cs`, partial `Game`): `VoiceUp(byte[])` client -> server and `VoiceDown(int speaker, byte[])` server -> client, both **unreliable on channel 2** (`VoiceTuning.Channel`; everything else uses channel 0), RPCs on `Game` like every other RPC. Server guards, in this order: `Net.IsVerified(sender)` and a registered name (a pending peer cannot speak; the engine also drops its RPCs, and `VoiceDown` is never sent to a peer that is not verified), frame size (`<= MaxFrameBytes` = 1000), then two token buckets per client (frames: 70/s, burst 14; bytes: 14000/s, burst 5000). Rejects are counted (`VoiceRejUnverified/Size/Rate`). Relayed frames carry the mode byte: `[seq lo][seq hi][mode][level][audio]`. The speaker never gets their own frames back. Late or reordered frames are dropped by the receiver (jitter buffer); the server buffers nothing.
- **Who hears whom** (the server decides, `VoiceRules.Decide`, pure and unit tested; the server only sends to listeners who may hear, so audio nobody should hear never leaves the server):

| Situation | Rule | Mode on the wire |
|---|---|---|
| Lobby and match-end screen | everybody hears everybody | 0 Global (not positional) |
| Round, living -> living | within 28 m of the speaker; the listener plays it 3D at the speaker's head: full volume within 6 m, squared fade to silence at 28 m | 1 Near |
| Round, downed speaker -> living | within 10 m only: full within 2 m, silent at 10 m, at 0.6 gain | 2 DownedNear |
| Round, living or downed -> ghost | from anywhere (the server does not know where a ghost floats), at 0.8 gain | 0 Global |
| Round, ghost -> ghost | everywhere | 0 Global |
| Round, ghost -> living or downed | never (nothing is sent) | - |
| Weighing (the Hall ceremony), living/downed -> living/downed | everybody hears everybody at full volume; ghosts still hear the living, the living still never hear ghosts | 0 Global |

  Ghost = a miner who is not alive (dead this round, thrown, left, or a late joiner). Positions are the server's `ServerPlayer.Pos` (the owner's reports).
- **Playback** (`VoiceHub`): per speaker a `JitterBuffer` (pure: reorders by 16-bit sequence number with wrap-around, skips frames that never arrive, drops late and duplicate frames, waits for 100 ms of audio before starting, drops the oldest audio above 400 ms; running dry ends in a 3 ms fade of the last sample and starting again fades in, so no clicks; a short utterance below 100 ms is released after 120 ms of silence) feeds an `AudioStreamGenerator` (0.25 s buffer, kept about 60 ms full) of an `AudioStreamPlayer3D` (attenuation model Disabled; the volume is set from the falloff every frame, panning stays) placed at the speaker's head (their `Miner` position + 1.6 m) or, for global voices, a plain `AudioStreamPlayer`. Distance also dulls the sound with a one-pole low-pass (the cutoff falls with distance), and all voices go through an own bus `Voice` with a small, quiet reverb for the cave feel. Muted peers (local only) are neither decoded nor played: their frames are counted and dropped. Voice volume (Settings, 0-150 %) scales everything.
- **Monsters hear voices** (`Game.ServerOnVoice`): while a living, not downed miner transmits above `NoiseLevelThreshold` (0.22; level = RMS / 0.25 of the audio, as the client reports it, clamped on the server) during a round, the server calls `Game.ServerNoise(pos, radius, miner)` at their position, **at most once per 0.7 s per speaker**, radius **6 m at the threshold up to 14 m at full level** (`VoiceRules.NoiseRadius`; for comparison a geode hit is 6-12, a sprint 8-20, dynamite 45; the miner's `NoiseMul`, e.g. the Hush stein, applies as for every noise). A whisper below the threshold and a downed or dead miner make none. All numbers are constants in `VoiceTuning.cs` (the "tuning file" of voice).
- **Feedback:** a small microphone bottom-left (above the bars) only while you transmit; a gold speaker over the head of a talking miner (a `Sprite3D` added to their `Miner`, texture drawn in code); a speaker and a **Mute** button next to every other name in the Tab overlay and in the lobby list. The Tab overlay is hold-to-show with a captured mouse, so holding Tab for 0.6 s frees the cursor (look and walk pause meanwhile) so the Mute buttons can be clicked; releasing Tab gives the mouse back (`VoiceHud`). One-time hint when you first transmit in a round: "Voices carry. Monsters hear them too." (`UserSettings.SeenVoiceHint`; not shown in automated runs). Settings: mode, a live mic level meter (the gold line is the open-mic gate) and Voice volume. Screenshot staging: `--fakesteam --screen=voice_settings | voice_talk | voice_score` (the last two in a round: `--host --autostart=1 --preset=debug --bot=idle`).
- **Tests:** `-- --voicecheck` (71 checks; also run by `tools/voice_test.sh`): falloff values and monotony, gain per mode, every (speaker, listener, phase) rule above, noise radius, level scaling, token buckets, jitter buffer (order, reorder, loss, late, duplicate, wrap-around, underrun fade without a step, resume fade-in, overrun bound, a randomised soak), fake codec and source. `tools/voice_test.sh` (env `PORT`, `LOGDIR`): headless host + 8 clients over ENet with the fake microphone and `--voicepin` positions (Host 60 m, Alice 0, Bob 4, Carol 17, Dave 50, Spam 90 on one axis; Gus and Gina join late as ghosts; one more client never answers the handshake). Asserted (PASS lines): lobby voice reaches everyone (global) and fills the playback buffer; Bob (4 m) hears Alice at gain 1.0, Carol (17 m) at 0.25, Dave (50 m) and the Host (60 m) get no frame at all; nobody receives their own voice; Bob muted Carol: her frames arrive but nothing is decoded or played, Alice still hears her; ghosts hear the living and each other, no living miner ever receives a ghost frame; in the weighing Dave at 50 m hears Alice globally; a whisper (level 0.05) is heard 10 m away but makes no `VOICE_NOISE`; Alice and Carol make noise events of 6-14 m radius, never closer than 0.7 s apart; a made-up unverified peer id is refused by `ServerOnVoice`; one oversized frame and a 300-frame burst are refused and the burst is capped for the listeners; the stalled (pending) client receives nothing and never registers. The staged positions (`VoiceTestPins`) are used by the server rules and by the listening client's gain; everything else is the production path.
- **Where this lives:** `Game.Voice.cs` is a partial `Game` file (new RPCs only), the rest is in `src/Net/Voice/*` and `src/UI/FriendsUi.cs`. Existing files touched additively: `UserSettings` (3 fields), `SettingsPanel` (one call), `Hud` (rebuild guard + one call in the Tab rows), `MenuUI` (one call in the lobby rows), `GuidePanel`, `RoomInfoPanel`, `Net` (Friends, CurrentLobbyId).
